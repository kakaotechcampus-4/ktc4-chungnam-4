# 커밋 만들기

## 메시지 형식

Conventional Commits — `feat` `fix` `refactor` `chore` `docs` `test` `style`

- **제목**: 영어 명령형, 50자 이내
- **본문**: 한국어로 **"왜"** 를 씁니다. 무엇을 했는지는 diff가 말해주므로 본문에 반복하지 않습니다.

```
refactor: move API conventions to tech spec

코드가 곧 명세가 되는 내용을 매 세션 로드되는 CLAUDE.md에 두지 않기 위함입니다.
멘토 리뷰(09/18) 반영 — docs/doc-management.md §원칙 ⑦.
```

## 커밋 분리

**섞지 않습니다.**

- 포맷팅 커밋 ↔ 로직 커밋
- 문서 커밋 ↔ 코드 커밋

리뷰어가 diff에서 의미 있는 변경만 보게 하려는 것입니다. 포맷터가 300줄을 바꾼 커밋에 로직 3줄이 섞이면 아무도 그 3줄을 못 봅니다.

문서 변경이 `[fix]`(문서가 현실과 다름)와 `[rule]`(규칙 자체가 바뀜)에 걸쳐 있으면 등급별로도 나눕니다. `[fix]`는 develop 직접 push가 허용되지만 `[rule]`은 PR + 팀 승인이라, 한 커밋에 섞이면 둘 다 승인 대기에 걸립니다 (`docs/doc-management.md`).

## 커밋 전 확인

금지 조항은 루트 `CLAUDE.md` §Git·§환경변수가 원본입니다 — 항상 로드되므로 여기 옮겨 적지 않습니다. 커밋 시점에 특히 걸리는 것만 짚습니다.

- 스테이징 목록에 `.env`·키·원아 미디어가 섞이지 않았는지 **파일 이름을 눈으로 확인합니다.** `git status --short`로 충분합니다.
- 커밋 금지 패턴이 빠져 있으면 `.gitignore`에 추가합니다. `.gitignore`가 목록의 원본입니다.
- 키가 이미 커밋됐다면 되돌리는 것으로 끝내지 말고 **즉시 폐기·재발급**하라고 사용자에게 알립니다. 히스토리의 blob은 지워도 남습니다.

## 이 도메인의 규칙

auth의 상세 작성 엔드포인트는 3개입니다. 교사·학부모 공용 로그인, 로그아웃, 현재 계정 정보입니다. 가입과 초대 API는 경로만 정했으므로 데모 계정은 시드 데이터로 넣습니다(제안).

**인증 (제안)**

- 인증 방식(세션 쿠키 vs JWT)은 아직 정하지 않았습니다. [확인 필요: 엄태은] 경로, 요청 본문, `/me` 응답은 어느 방식이든 같습니다.
- 교사 계정이 학부모 경로로 들어오는 식의 역할 불일치는 FE가 `/me`의 `account_type`으로 먼저 막습니다.
- 모든 API에 걸리는 규칙(공통 에러 코드, 401·403 처리, 목록·enum·경로 규칙)은 테크스펙 §공통 API 규약과 [README](README.md) §공통 규약 중 테크스펙에 없는 것에 있습니다.

**인증 방식별 차이** (경로·본문은 같음)

| 항목 | 세션 쿠키 | JWT |
|---|---|---|
| 로그인 응답 | `Set-Cookie`(HttpOnly·Secure·SameSite) | 본문에 `access_token`·`token_type`·`expires_at` 추가 |
| 이후 요청 | `credentials: "include"` | `Authorization: Bearer <token>` |
| 로그아웃 | 서버 세션 삭제 + 쿠키 만료 | 클라이언트가 폐기. 서버 무효화는 선택 |
| 따로 정할 것 | CSRF 방어 | 토큰 보관 위치, refresh 토큰 |

**경로를 이렇게 정한 이유**

- `/auth/login`처럼 동사를 넣은 경로는 복수 명사 규약에 어긋납니다. 그래서 로그인은 세션 생성(`POST /sessions`), 로그아웃은 세션 삭제로 봅니다.
- `/me`는 "지금 로그인한 계정"을 가리키는 단수 별칭으로, 규약의 예외입니다.

## 상세 작성 엔드포인트

### `POST /api/v1/sessions` — 이메일·비밀번호 로그인(교사·학부모 공용)

- 쓰는 화면: 로그인
- 요구사항: FR-13
- 권한: 로그인하지 않은 누구나. 역할은 따로 고르지 않고, 서버가 `Account.account_type`(`teacher`/`parent`)으로 판별합니다.
- 요청: 본문

```json
{ "email": "hanul.kim@example.com", "password": "example-password" }
```

- 응답 `201`:
  - FE는 `account_type`으로 첫 화면을 고릅니다. 교사는 오늘의 기록, 학부모는 W3입니다.
  - 헤더에 쓸 정보는 `GET /api/v1/me`로 따로 받습니다.

```json
{ "account_id": "ac000000-0000-4000-8000-000000000001", "account_type": "teacher" }
```

- 에러: `INVALID_CREDENTIALS` (401) — 없는 이메일이거나 비밀번호가 틀렸을 때. 두 경우를 구분하지 않고 같은 메시지를 씁니다.
- [확인 필요: 엄태은] FR-13은 "학부모와 선생님 중 선택해서 로그인"인데, Figma 로그인 화면에는 역할 선택이 없습니다. 공용 로그인을 제안하고, FR 문구 수정은 팀이 정합니다.
- [확인 필요: 엄태은] 학부모는 원아별 초대 링크로 가입하며 동의합니다(09-22 결정, FR-28). 링크의 발급 주체·형식·만료와 본인 인증 방식(SMS 여부)을 정해야 합니다. 로그인 반복 실패를 제한할지, 제한한다면 어떤 상태 코드를 쓸지도 정해야 합니다. 공통 규약의 상태 코드 목록에는 429가 없습니다.

### `DELETE /api/v1/sessions/current` — 로그아웃

- 쓰는 화면: 접근 권한 없음의 "다른 계정으로 로그인 →"
- 요구사항: FR 없음
- 권한: 로그인한 교사·학부모. `current`는 "이 요청의 세션"을 뜻하는 별칭입니다.
- 요청: 파라미터와 본문 없음
- 응답 `204`: 본문 없음. 쿠키 방식이면 쿠키를 만료시키는 `Set-Cookie`를 함께 보냅니다.
- 에러: 없습니다. 이미 만료된 세션으로 불러도 `204`를 돌려줍니다(멱등, 제안).
- [확인 필요: 엄태은] JWT라면 로그아웃할 때 서버에서도 토큰을 무효화할지 정해야 합니다.

### `GET /api/v1/me` — 로그인한 계정 정보와 역할

- 쓰는 화면:
  - 로그인 직후 라우팅 가드
  - 교사 공통 헤더의 선생님 이름: 오늘의 기록·빈 상태, 초안 검토/왼쪽 원아 목록 등 상세 작성 범위의 교사 화면 전체
  - 접근 권한 없음의 "내 홈으로 돌아가기"
  - 학부모 W3·W4의 상단 계정 표시
- 요구사항: FR-13
- 권한: 로그인한 본인만
- 요청: 파라미터 없음
- 응답 `200`: `account_type`에 따라 교사용 `TeacherMe`와 학부모용 `ParentMe` 중 하나입니다(제안).

교사:

```json
{
  "account_id": "ac000000-0000-4000-8000-000000000001",
  "account_type": "teacher",
  "email": "hanul.kim@example.com",
  "name": "김하늘",
  "teacher_id": "7e000000-0000-4000-8000-000000000001",
  "center_id": "0c000000-0000-4000-8000-000000000001"
}
```

학부모:

```json
{
  "account_id": "ac000000-0000-4000-8000-000000000002",
  "account_type": "parent",
  "email": "parent01@example.com",
  "name": "김서연",
  "parent_id": "9a000000-0000-4000-8000-000000000001"
}
```

- 반 목록과 어린이집명은 `GET /api/v1/classes`, 학부모의 자녀는 `GET /api/v1/me/children`에서 받습니다(둘 다 organization). 같은 값을 한 곳에서만 줘서 서로 어긋나지 않게 합니다.
- 헤더에서 고른 반은 서버에 저장하지 않고 FE가 들고 있습니다. 임시 결정(송유진): 고른 반의 `class_id`만 브라우저(localStorage)에 두고, `GET /api/v1/classes`에 없는 반이면 첫 번째 반을 씁니다.
- 비밀번호 해시와 연락처는 싣지 않습니다. 원장의 권한 차이가 스펙에 없어 `Teacher.role`도 뺐습니다.
- 에러: 공통 에러만
- [확인 필요: 엄태은] 역할 필드 이름을 정해야 합니다. 데이터 모델은 `account_type`, `auth/CLAUDE.md`는 `role`입니다. `Teacher.role`(담임/원장)과 겹치지 않도록 `account_type`을 제안합니다.
- [확인 필요: 엄태은] 세션·토큰 만료 시간을 정해야 합니다. 100~150장을 올리는 도중에 끊기지 않아야 합니다. CurrentUser에 `class_ids`를 담을지도 정해야 하며, 요청마다 조회하는 쪽을 제안합니다.

## 경로만 정한 엔드포인트

경로만 정했습니다. 요청·응답은 그 화면을 만들 때 이 파일에 먼저 채웁니다(PR). 어느 화면이 쓰는지는 [screens.md](screens.md)에 있습니다. "확장(경로만)"은 위 상세 작성 엔드포인트에 필드나 파라미터를 더하는 것입니다.

| 메서드·경로 | 하는 일 | 단계 | BE 담당 |
|---|---|---|---|
| `POST /api/v1/accounts` | 교사 회원가입 | 경로만 | 엄태은(`center_code` 검증은 이한나) |
| `POST /api/v1/password-resets` | 비밀번호 재설정 링크 보내기 | 경로만 | 엄태은 |
| `PATCH /api/v1/me` | 내 계정 정보 고치기 | 경로만 | 엄태은 |
| `POST /api/v1/sessions` | `remember_me`(로그인 유지) 추가 | 확장(경로만) | 엄태은 |
| `GET /api/v1/me` | `onboarding_step`(온보딩 진행 단계) 추가 | 확장(경로만) | 엄태은 |

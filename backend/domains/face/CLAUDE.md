# ③ face — 얼굴 임베딩 (NFR-01 보안 격리)

얼굴 임베딩의 암호화 저장·관리. 담당: 김동건. 공통 규칙은 [../../CLAUDE.md](../../CLAUDE.md).

## 파일 (목표 구조·구현 예정 포함)

| 파일 | 내용 |
| --- | --- |
| `models.py` | `FaceEmbedding`, `EmbeddingLifecycleLog` |
| `schemas.py` | 임베딩 등록·조회 |
| `router.py` | `/face` 엔드포인트 |
| `service.py` | AES 암복호화, KMS 키 참조 |

## 규칙

- **얼굴 임베딩 등록용 원본 사진은 서버·S3로 올라오지 않습니다** (H-3). 브라우저에서 임베딩을 추출한 뒤 원본을 폐기하고, 이 도메인은 벡터만 받습니다. 활동 사진·영상의 업로드는 media의 별도 흐름입니다.
- S3를 거치지 않습니다. media는 presigned URL로 파일을 S3에 올리고 메타데이터만 DB에 남기지만, face는 올릴 파일이 없습니다 — 브라우저가 계산한 임베딩 벡터를 API 요청 본문으로 직접 받아 즉시 암호화해 DB에 저장합니다.
- 임베딩은 DB에 암호화해 저장합니다. 온디바이스 비교를 위한 캐시 조회에서는 인증된 교사의 담당 반에 속한 등록·동의 원아만 필터링한 뒤 복호화한 기준 임베딩을 HTTPS 응답으로 전달할 수 있습니다. 학부모·외부 사용자·다른 반에 대한 응답이나 LLM 요청에는 포함하지 않습니다.
- 브라우저는 전달받은 임베딩을 이번 배치 동안만 임시 캐시하고 배치 종료 시 폐기합니다. 캐시 조회에 실패하면 얼굴 비교 처리를 중단합니다. 평문 임베딩은 로그·예외 메시지에 기록하지 않으며 식별이 필요하면 ID만 사용합니다 (H-4).
- 생성·갱신·파기는 전부 `EmbeddingLifecycleLog`에 남깁니다. 파기는 `audit`의 `DeletionLog`에도 기록합니다 (NFR-05).
- 암복호화 로직은 우선 `service.py`에 구현할 예정입니다. 커지면 `core/crypto.py`로 분리 검토.
- 키는 코드에 박지 않고 `core/config.py`의 `Settings`(KMS 키 참조)로 읽습니다.

## 다른 도메인과의 관계

- `organization`: `Child` FK, 동의 철회 시 임베딩 파기 대상 판정
- `audit`: 파기 로그

# audit — 접근 · 파기 로그

담당: 미정

> **H-4가 직접 걸리는 도메인입니다.**

## 소유 테이블

| 테이블 | 핵심 필드 | 메모 |
|---|---|---|
| `AccessLog` | id, created_at | 누가/언제/무엇을 열람했는지 (NFR-05) |
| `DeletionLog` | id, reason, deleted_at | 원본 파기 이력 (NFR-04) |

## 요구사항

- NFR-04 파기 기록 · NFR-05 열람 기록

## 규칙

- **로그 테이블은 append-only입니다.** update·delete를 만들지 않습니다.
- **개인정보·로그성 테이블을 물리 삭제하지 않습니다.** 파기는 `DeletionLog` 기록과 함께 일어납니다.
- 로그에 남기는 건 **ID뿐**입니다. 실명·전화번호·이메일·토큰·임베딩 값을 컬럼에 넣지 않습니다 (H-4).
- 열람 API는 **전부** `AccessLog`를 남깁니다. 이건 필수 테스트 4번이라 누락되면 머지가 막힙니다.
- 다른 도메인은 `audit.service`의 기록 함수만 호출합니다. `AccessLog` 모델을 직접 import하지 않습니다.

## 미정

- 로그 보존 기한과 아카이빙 정책

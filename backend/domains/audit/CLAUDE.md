# ⑦ audit — 접근·파기 로그 (NFR-04, NFR-05)

열람과 파기 기록. 담당: 한상균. 공통 규칙은 [../../CLAUDE.md](../../CLAUDE.md).

## 파일 (목표 구조·구현 예정 포함)

| 파일 | 내용 |
| --- | --- |
| `models.py` | `AccessLog`, `DeletionLog` |
| `service.py` | 폴리모픽 기록 |

`router.py`는 없습니다. 조회 API가 필요해지면 그때 추가합니다.

## 규칙

- 대상이 어느 도메인이든 받을 수 있게 폴리모픽(`target_type` + `target_id`)으로 기록합니다. 도메인마다 로그 테이블을 따로 만들지 않습니다.
- 다른 도메인은 이 도메인의 `service.py` 함수만 호출하고 `AccessLog`/`DeletionLog`에 직접 INSERT하지 않습니다. audit은 유일하게 역방향 호출이 허용되는 도메인입니다.
- **로그에 개인정보를 넣지 않습니다** (H-4). 실명·연락처·이메일·토큰·임베딩 값 대신 ID만 남깁니다.
- 로그는 수정·삭제하지 않습니다. 추가만.
- 기록 실패가 본 작업을 조용히 통과시키면 안 됩니다. 열람 API는 로그가 남는 것을 보장하고 실패 시 드러나게 하세요.

## 다른 도메인과의 관계

- 전 도메인이 기록 대상. 특히 `documents` 열람, `face` 임베딩 파기, `media` 원본 파기
